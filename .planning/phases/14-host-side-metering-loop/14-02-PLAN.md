<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host CLI ↔ SSHFS-mounted sandbox FS | The host revenium CLI reads sandbox-controlled OpenClaw JSONL logs through the mount and writes guardrail-status.json back. The sandbox can influence the content of those logs. |
| operator/install args → crontab + mount commands | `--sandbox <name>` flows into the `nemoclaw share mount` invocation and the crontab marker/line. |
| REVENIUM_API_KEY → host-env file | The Revenium secret is persisted on the host and sourced each tick. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03 | Information Disclosure | REVENIUM_API_KEY in ~/.nemoclaw/revenium-host.env | mitigate | written via printf (never a CLI flag), `chmod 600` immediately; key never placed in the crontab line, process args, or echoed output (GROUP D asserts) |
| T-14-04 | Injection | sandbox name interpolated into `nemoclaw share mount` argv and the crontab line | mitigate | sandbox name passed as a separate argv token to nemoclaw (not shell-evaluated); crontab line built with the marker appended after a literal `#` comment so a crafted name cannot inject a second cron field; install validates the name is non-empty. Residual: an operator supplying a malicious `--sandbox` value is a trusted-operator action, not a remote vector — accept residual |
| T-14-05 | Tampering | guardrail-status.json written back through a sandbox-controlled mount | mitigate | the host wrapper never writes a false all-clear on failure (exit 3, write-nothing, D-05); the shared atomic-write guardrail-check.sh (unmodified) performs the only write; staleness is detectable via frozen updatedAt + post-write _maxAgeSeconds (D-06) consumed by Phase 15 |
| T-14-06 | Denial of Service | per-tick `nemoclaw exec` leaking hung node processes (SC2) | mitigate | the tick uses SSHFS file I/O + cron.sh only; no `nemoclaw exec` anywhere (grep-asserted); mount-down path exits 3 immediately and never hangs (SC3) |
| T-14-SC | Tampering | sshfs auto-install via apt-get/dnf | accept | distro package managers install signed OS packages (sshfs / fuse-sshfs) from configured repos, not third-party npm/pip/cargo; no Package Legitimacy Gate applies. Failure is a hard-gate abort, not a silent fallback |
