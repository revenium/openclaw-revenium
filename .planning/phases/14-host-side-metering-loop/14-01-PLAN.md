    marker line landed in the crontab, sshfs was/ wasn't called). Use `set -uo pipefail` (NOT -e — manage

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test harness → host system | The harness must NOT mutate the real crontab, mount real sshfs, or run the real nemoclaw binary. All such commands are intercepted by PATH-prepended stubs into an isolated tmp HOME. |
| captured argv → shell | Stub-captured argv (including sandbox names) is data, never code. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | tests/test_nemoclaw_cron.sh mutating the developer's real crontab | mitigate | crontab is stubbed via stub-mount-env.sh writing to STUB_CRONTAB_FILE in a tmp HOME; the real `crontab` binary is never on the test PATH |
| T-14-02 | Elevation/Injection | sandbox name interpolated into stub argv comparisons | mitigate | stubs string-compare argv with grep -qF / case only; harness/stub contain no `eval` (asserted by acceptance criteria) |

| T-14-SC | Tampering | npm/pip/cargo installs | mitigate | none — this plan installs no packages (pure bash test scaffold); no Package Legitimacy Gate triggered |
