<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session JSONL → CLI argv | `toolCall.name`, `toolCall.id`, timestamps, and tool-result error text are read from session files (attacker-influenceable if tampered) and flow into `meter tool-event` argv and `TOOLEV:` ledger keys. |
| report.sh → tool-events endpoint | Tool-events carry the configured Revenium API key via the CLI; argv must never embed the key or shell metacharacters. |
| python3 heredoc | The extractor reads the raw session file; the file path is the only attacker-influenceable input and is passed via env, not interpolated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02-01 | Tampering | tool-result error text → `--error-message` argv | mitigate | Error text truncated to 256 chars in the python3 extractor and passed as a single argv-array element (`cmd+=(--error-message "${error_msg}")`), never string-interpolated into a shell command or log template. |
| T-10-02-02 | Tampering | toolcall_id → `TOOLEV:` ledger key | mitigate | Dedup uses `grep -qF` (fixed-string, not regex) so a crafted id cannot act as a pattern; the id is a content item id from the session, not user free-text. |
| T-10-02-03 | Tampering | crafted session JSONL → injection into argv | mitigate | SESSION_FILE passed via env to a single-quoted `<<'PY'` heredoc (no bash expansion of file content); all extracted values cross into bash only as TAB-separated fields read with `IFS=$'\t' read -r`, then placed as discrete argv-array elements. |
| T-10-02-04 | Denial of Service / Repudiation | tool-event failure or flood masking completion metering | mitigate | Scan loop runs AFTER completion stamping (Pitfall 6); `_meter_tool_event` is fail-open (`return 0`, `warn` only) and never touches `failed_count`/`reported_count`, so the CR-02 offset gate and completion records are never blocked. Cron flock prevents concurrent-tick double-emission; `TOOLEV:` ledger prevents within/cross-tick duplicates. |
| T-10-02-05 | Information Disclosure | API key leakage into ledger/logs | mitigate | Only tool id, duration, and truncated error text are logged; the API key lives in the CLI config, never read or echoed; hermetic stub tests assert no key in captured argv. |
| T-10-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs (RESEARCH.md Package Legitimacy Audit: N/A). |
</threat_model>
