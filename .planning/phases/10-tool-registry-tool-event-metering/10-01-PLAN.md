<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session JSONL → CLI argv | Tool names are read from session `toolCall.name` (attacker-influenceable if a session file is tampered) and flow into `revenium tools create --name/--tool-id` and into ledger keys. |
| skill → revenium CLI | The CLI carries the configured Revenium API key; argv must never embed the key or shell metacharacters. |
| report.sh → ledger files | Ledger writes under OPENCLAW_HOME; a poisoned ledger could suppress a legitimate registration or inject log noise. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01-01 | Tampering | tool name → `tools create` argv | mitigate | `normalize_tool_id` strips to URL-safe chars (`__`→`--`, `_`→`-`, lowercase); names are passed as discrete argv-array elements (`cmd+=(--name "${tool_name}")`), never string-interpolated or `eval`'d. |
| T-10-01-02 | Tampering | tool_id → ledger key / log line | mitigate | Ledger key is the normalized id; log lines truncate to 64 chars (`${tool_id:0:64}`, T-04-08). `grep -qF` (fixed-string) used for dedup so a crafted id cannot act as a regex. |
| T-10-01-03 | Denial of Service | `tools create` hang/error blocking the tick | mitigate | `_register_tool` is fully fail-open (`return 0` on every path, `warn` on failure); never touches `failed_count`/`reported_count`; gated behind TOOLS_CLI_CAPABLE so a missing/broken CLI skips all tool work. |
| T-10-01-04 | Information Disclosure | API key leakage into logs/ledger | mitigate | Only the normalized tool id and tool type are logged; the API key lives in the CLI's own config, never read or echoed by report.sh; stub-based tests assert no key in argv. |
| T-10-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs (RESEARCH.md Package Legitimacy Audit: N/A — no new deps). |
</threat_model>
