Both handlers append newline-delimited JSON to a single capture file, mirroring this project's existing `markers/*.jsonl` append convention. Keep the handlers synchronous-cheap: a blocking write on every completion is itself a soak-relevant cost, and plan `17-05` will measure it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sidecar plugin -> OpenClaw runtime | Third-party code running inside the agent's own turn loop, on both the host gateway and the sandbox gateway |
| plugin install -> trust/provenance record | `openclaw plugins install` establishes provenance; a hand-placed plugin loads with inert hooks |
| captured completions -> committed repository | `llm_output` sees completion content; what gets retrieved into git is a disclosure decision |
| host gateway <-> sandbox gateway | The same plugin installed on both sides of the D-13 shared host |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-17-08 | Denial of Service | A hand-rolled sidecar hangs the agent turn, as spike 006's stub did | high | mitigate | Scaffold from `openclaw plugins init` or mirror a real compiled plugin; handlers do nothing but append a JSON line; if a turn hangs anyway, record it verbatim as candidate (c)'s result and stop rather than iterating on a destabilizing plugin on a shared host. |
| T-17-05 | Information Disclosure | `llm_output` payloads carry completion content; `after_tool_call` carries tool arguments and results | medium | mitigate | Handlers capture usage numbers, ids, tool names, durations and error flags — not message bodies; anything retrieved into the repository is redacted before commit. Acceptance criteria assert no raw prompt text in `sidecar-capture.jsonl`. |
| T-17-09 | Elevation of Privilege | `allowConversationAccess: true` grants the probe plugin access to conversation content it does not need beyond usage metadata | medium | mitigate | The permission is required for `llm_output` to register at all, so it is granted; the plugin reads no conversation content beyond the `usage` object and tool metadata, matching the existing `revenium-marker-gate` precedent where the same permission is set and no conversation content is read. The plugin is throwaway and is removed from both gateways when the phase completes. |
| T-17-02 | Tampering | The same plugin id installed on both pairings makes a firing result ambiguous as to which gateway produced it (D-13) | medium | mitigate | Capture file blocks are labelled per pairing on retrieval; `openclaw plugins inspect` provenance is confirmed separately on each side before any firing result is trusted. |
| T-17-SC | Tampering | The `plugins init` scaffold's own dependency graph | medium | mitigate | The scaffold is generated by the already-installed `openclaw` toolchain rather than fetched from a third-party registry entry; no new package is added to this repository's dependency graph.
