<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| skill post-install → host openclaw config | The install step mutates the host's openclaw plugin config (enable + allowConversationAccess) |
| installed plugin → gateway hook registry | The plugin registers conversation hooks that run on every turn finalize |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-silent-block | Tampering / Repudiation | conversation-hook registration | mitigate | post-install runs `openclaw plugins inspect` and warns if `before_agent_finalize` is absent from hookNames — the silent-block failure mode is surfaced, not hidden |
| T-11-install-failopen | Denial of Service | post-install plugin step | mitigate | Every command is `warn`-and-continue and guarded by `command_exists openclaw`; a failed install never aborts the skill install |
| T-11-no-autorestart | Tampering | host gateway lifecycle | accept | post-install documents the required restart but does not restart the host gateway itself (a skill must not control host process lifecycle); restart is a documented manual step |
| T-11-conv-access | Information Disclosure | allowConversationAccess: true grant | mitigate | The flag is required by the SDK to register the hooks, but the plugin reads no conversation content — it only observes exec tool calls via before_tool_call (privacy intent preserved; verified in Plan 01 unit tests) |
</threat_model>
