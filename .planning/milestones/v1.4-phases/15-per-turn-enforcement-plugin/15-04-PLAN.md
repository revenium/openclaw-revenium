<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OpenClaw gateway process → run-state file on disk | The plugin (untrusted-input-adjacent: runId originates from the host dispatcher) writes/reads a JSON state file under OPENCLAW_HOME. A malicious or malformed runId, or a hostile pre-existing file, crosses this boundary. |
| install script (host) → sandbox via `nemoclaw exec` | Gate A parses agent JSON returned across the sandbox boundary; the JSON is attacker-influenceable in principle (prompt content). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-RS-01 | Tampering | `runStatePath(runId)` in gate.js | mitigate | Sanitize runId to a safe basename (`[A-Za-z0-9._-]` only, reject empty after sanitize) before `path.join` — a `../` runId cannot escape the run-state dir. Asserted by a traversal unit test. |
| T-15-RS-02 | Spoofing | persisted exec/marked state | mitigate | State file holds only `{exec, marked, updatedAt}` — no command content, no secrets. A forged file can at most cause an extra revise pass (bounded by `maxAttempts:1`) or a missed marker; it cannot block the reply (fail-open) or leak data. Accept the bounded extra-revise risk; it degrades gracefully. |
| T-15-RS-03 | Information Disclosure | run-state file readability | mitigate | Write with mode `0o600` (owner-only). The file contains no PII/secrets regardless, but owner-only prevents other sandbox users reading session runIds. |
| T-15-RS-04 | Denial of Service | unbounded run-state file growth | mitigate | `handleAgentEnd` deletes the per-runId file (best-effort). Files are tiny (<100 bytes) and keyed per active run; cleanup prevents accumulation. A cleanup miss leaks one small stale file, not unbounded growth. |
| T-15-RS-05 | Denial of Service | fs failure blocks the agent reply | mitigate | All fs operations are inside inner try/catch that swallows; the outer `safe*` wrappers are a second containment layer. An unwritable state dir degrades to the prior in-process-only behavior, never a thrown/blocked turn. Asserted by a fail-open unit test. |
| T-15-RS-06 | Tampering | Gate A JSON parse over `nemoclaw exec` | accept | Gate A reads `promptChars` (an integer) from agent JSON; the threshold compare is numeric. Worst case a manipulated prompt inflates promptChars and passes a gate that should fail — but Gate B (`plugins inspect` trusted hooks) independently proves the plugin is loaded/trusted, so a single spoofed promptChars cannot alone green-light a broken install. Low value, defense-in-depth via Gate B. |
| T-15-RS-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan (only `node:fs`/`node:path` builtins). slopcheck N/A; no `[ASSUMED]`/`[SUS]` packages introduced. |
</threat_model>
