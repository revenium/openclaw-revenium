<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied skill dir → `nemoclaw skill install` | The path passed to `nemoclaw skill install` is resolved from `${SCRIPT_DIR}/..`; on a home-directory install with SSHFS mounts present, a wrong path resolution feeds SSHFS-tainted sibling directories (node_modules with unsafe filenames) into the installer (V5 Input Validation). |
| in-sandbox `openclaw skills list` output → install gate | Untrusted command output is grepped to decide pass/fail; a parsing failure must fail closed, not silently pass. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Tampering / Input Validation | `install_skill_nemoclaw()` skill-dir resolution → `nemoclaw skill install` | mitigate | SKILL.md presence guard fails hard with an actionable message when the resolved dir lacks SKILL.md, preventing a wrong/SSHFS-tainted path from being passed to `nemoclaw skill install` (which would otherwise abort opaquely on unsafe filenames). |
| T-16-02 | Spoofing / silent false success | `✓ ready` discovery assertion parsing `openclaw skills list` | mitigate | The assertion fails closed: the `|| true` guard captures output without aborting, then a `grep -q` mismatch triggers `fail` — a missing/garbled skill listing cannot masquerade as a successful deploy. |
| T-16-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — it modifies an existing bash script and bash test harness; no new dependencies. |
</threat_model>
