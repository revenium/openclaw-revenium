<objective>
Close the GUARD-03 / GUARD-04 producer-side gap and CR-02 in `scripts/guardrail-check.sh`.

The root cause of the GUARD-03/04 gap is that `new_halted = autonomous and any_blocked` is always `false` when `autonomousMode=false`, and the status file emits no other signal a consumer (SKILL.md) could act on. This plan adds a separate `warned` boolean and `warnedRules[]` array to `guardrail-status.json` so the warn-and-ask consumer in SKILL.md (plan 03-07) has a real data flow to read. The halt path (`halted`) is unchanged — `warned` is an independent signal for the non-autonomous case.

CR-02 (a code-review critical) is fixed in the same file: the `HALT_OUTPUT=$(... python3 ...)` subshell has no `|| true` guard, so under `set -euo pipefail` a write failure aborts the whole script non-zero, violating the documented fail-open contract.

Purpose: Restore the broken warn-and-ask data flow for `autonomousMode=false` (GUARD-03/04) and harden the status-write against the documented fail-open posture (CR-02).
Output: Updated `scripts/guardrail-check.sh` emitting `warned`/`warnedRules` and guarded against status-write failure.
</objective>
