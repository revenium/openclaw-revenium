<objective>
Close the always-on per-turn enforcement gap discovered during deploy-readiness review. Plans 03-06/03-07 added the `warned` producer signal (guardrail-check.sh) and a warn-and-ask consumer branch in SKILL.md. But the two ALWAYS-ON injection points that actually run on every agent turn on a real host — the AGENTS.md section injected by `post-install.sh`, and the per-session `BUDGET-GUARD.md` directive — only branch on `halted`. In the default non-autonomous mode a budget breach yields `halted:false, warned:true`, so both injection points read `halted:false` and tell the agent "proceed silently." The warn-and-ask never fires end-to-end.

This plan makes both always-on injection points learn the `warned` branch, strictly ADDITIVELY: insert a `warned:true` case BETWEEN the existing halted-false and halted-true logic, pointing at SKILL.md's warn-and-ask section (mirroring how the halted-true bullet already points at SKILL.md's HALT CHECK). The existing `halted:true` halt bullets stay byte-for-byte unchanged. It also fixes README.md doc drift where the deleted `budget-status.json` file is still referenced.

Purpose: Deliver GUARD-03/GUARD-04 (warn-and-ask) on the enforcement surfaces that actually execute per-turn, not just the on-demand SKILL.md path.
Output: Updated `scripts/post-install.sh` (AGENTS.md injection) and `BUDGET-GUARD.md` (per-session directive) with the warned branch; `README.md` doc drift corrected.
</objective>
