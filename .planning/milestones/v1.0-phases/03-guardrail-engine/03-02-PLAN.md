<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Revenium API → guardrail-check.sh | enforcement-rules / budget-rules JSON is parsed and rule names are embedded in logs and notifications |
| guardrail-check.sh → guardrail-status.json | the file the agent trusts for halt decisions; partial writes would corrupt enforcement |
| guardrail-check.sh → openclaw message send | rule name flows into the notification message string |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | rule `name` embedded in log lines | mitigate | Truncate to 64 chars before logging: `name = (match.get('name') or '')[:64]` (Security Domain pattern). Rule name originates from the Revenium API, not direct user input |
| T-03-05 | Tampering | partial guardrail-status.json read during write | mitigate | Atomic write via tempfile.mkstemp in same dir + os.replace (D-14 / Pattern 4); never write the status file in place |
| T-03-06 | Tampering | rule name interpolated into openclaw message send MSG | mitigate | Build MSG via quoted bash variable expansion of the API-sourced name; name is not attacker-controlled shell input. No eval; no unquoted expansion into a command |
| T-03-07 | Denial of Service | guardrail-check.sh failure aborts cron | mitigate | Fail-open: every preflight and failure path exits 0; cron wrapper uses `|| true`. Cron never emits error mail |
| T-03-08 | Information Disclosure | API JSON written to status file | accept | guardrail-status.json contains only budget metrics (currentValue, hardLimit) and rule names — no secrets. File lives under HOME with user umask |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan; uses pre-existing revenium and openclaw CLIs only |
</threat_model>
