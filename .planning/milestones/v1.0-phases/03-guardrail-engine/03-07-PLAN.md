<objective>
Close the GUARD-03 / GUARD-04 consumer-side gap in `SKILL.md` and the CR-01 critical in `scripts/setup-guardrails.sh`.

GUARD-03/04 require a warn-and-ask path for the default `autonomousMode=false` mode. Plan 03-06 makes `guardrail-check.sh` emit a `warned` / `warnedRules` signal. This plan adds the SKILL.md branch that consumes it: when `warned` is true, the agent warns the user with spend context (rule name, currentValue vs hardLimit) and asks permission before continuing — instead of the current silent proceed.

CR-01 (a code-review critical) is fixed in the same wave: the `setup-guardrails.sh` `[r]ecreate` path deletes all Revenium rules but does not clear `ruleIds` from `config.json`. If the subsequent `create_rule` fails and the script `exit 1`s, `config.json` still holds the now-deleted rule IDs. The SKILL.md setup gate then sees a non-empty `ruleIds` and considers setup complete, leaving the halt mechanism silently broken.

Purpose: Deliver the user-visible warn-and-ask behavior (GUARD-03/04) and prevent stale ruleIds from silently disabling guardrails after a failed recreate (CR-01).
Output: Updated `SKILL.md` (warn-and-ask branch) and `scripts/setup-guardrails.sh` (ruleIds cleared on recreate).
</objective>
